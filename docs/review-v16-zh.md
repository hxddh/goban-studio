# Goban Studio v16.0.0 发布后评估与 v17 规划

评估日期：2026-11-15 · 对象：`main` @ `50ba807`（v16.0.0，已发布）· 依据：v16 的执行记录（`docs/review-v15-zh.md` 附录）、仓库所有者反馈的“语言设置不生效”、PR #23 中打包后自检的新检查结果、依赖的上游版本。

## 0. 结论

**v16 发布后发现了一个严重的 macOS 专属缺陷，应先发补丁版。**

- **现象**：仓库所有者反馈“语言设置不生效”。
- **原因**：PR #23 给打包后自检加了语言检查，第一次运行就找到了原因。macOS 的 WebView 读取应用自带文件（`zero://app`）时，返回**状态码 0、没有内容类型，但文件内容完整**（中文字符串 36 KB 全部到达）。应用里每处读取都要求 `r.ok`，于是把这些文件都丢掉了。
- **影响（仅 macOS）**：
  - 设置里换语言后仍是英文；
  - 启动后按需读取的内容（课程、题目、名局）、布局库和落子采样音都读不到；
  - Windows 返回 200，不受影响。
- **为什么到发布后才发现**：
  - 浏览器里一切正常，所有界面检查都在浏览器里跑；
  - 打包后自检只检查引擎和桥接，不碰这些文件；
  - 三个平台的打包 CI 全绿，但没有一项检查读过这些文件。
- **修复**：已在 PR #23。新增 `local-file.js`，接受“ok 或状态 0 且有内容”，四处读取都改用它。打包后自检新增两项必过检查：`languages` 和 `localFiles`。
- **建议**：
  1. 立即发 **v16.0.1**，只含这个修复（已于 2026-11-16 发布）。
  2. **v17 定为“稳”**：不加功能，让已有的东西在真实的打包应用里可靠，补齐内容，修掉看得见的粗糙处（§3.2）。

| | v15 → v16 的判断 | 这次说明了什么 |
| --- | --- | --- |
| 能在 CI 里验证的 | “基本都验证了” | 只验证了**浏览器里**的应用和打包应用的**引擎**；打包应用的界面路径没有被走过 |
| 只有真机能验证的 | Metal、AVX2、断电、标题栏 | 还要加上：macOS 上的整个界面（语言、课程、名局）——现在 CI 的自检能覆盖一部分 |

## 1. 这个缺陷本身

| 项目 | 内容 |
| --- | --- |
| 受影响版本 | v16.0.0 已实测受影响。按需读取内容从 v9 就有，语言文件从 v14 开始单独存放；macOS 外壳从哪个版本开始返回状态 0（例如 v15 的 Native SDK 0.11.1 升级），从这里无法确定 |
| 受影响平台 | macOS（Apple Silicon 和 Intel，同一个 WebView）；Windows 不受影响 |
| 用户看到的 | 换语言无效；打开课程或题目时出现“内容读取失败，重试”（重试也无效）；布局探索没有数据；落子声退回合成音 |
| 修复 | `src/web/js/local-file.js`；`i18n.js`、`content.js`、`explorer-ctl.js`、`audio.js` |
| 防止复发 | 打包后自检必过 `languages`（读文件、按设置的方式切换、检查侧栏）和 `localFiles`（全部内容、布局库、一个音效）；单元测试禁止任何读取再自带 `r.ok` 判断；界面检查覆盖设置里的语言切换 |
| 根本原因 | 外壳对自带文件返回的不是 HTTP 响应。也可以在 Zig 一侧修（返回 200 和内容类型），但那要改 Native SDK 的 macOS 宿主代码；JS 一侧的修复更小，且对两种返回都成立 |

## 3. 规划

### 3.1 v16.0.1（已发布，2026-11-16）

只含 PR #23：macOS 上读取应用自带文件的修复，以及新的自检和界面检查。三个平台的打包后自检都通过了 `languages` 和 `localFiles`。

### 3.2 v17：稳（具体内容）

**方向不变**：一个安静、离线的围棋应用，从第一颗子学起，和自己选的棋力对局，用 KataGo 复盘每一局。

**v17 不加新功能、不加设置项、不加新页面。** 只做三件事：

- 让已有的东西在真实的打包应用里可靠；
- 补齐 v16 新网络留下的内容缺口；
- 修掉看得见的粗糙处。

#### A. 可靠（用户看不见，但最要紧）

| # | 内容 | 衡量 |
| --- | --- | --- |
| A1 | **在打包后的 Windows 应用里跑核心界面检查**。WebView2 开调试端口，Playwright 通过 CDP 连上，跑一组现有的界面检查：<br>• 换语言<br>• 打开一课、做一道题<br>• 打开一局名局<br>• 布局探索<br>• 下一手、认输、进入复盘 | PR 的 `package-windows` 里这组检查全部通过；检查代码复用 `scripts/ui-tests`，不另写一套 |
| A2 | **macOS 自检走一遍同样的路径**（WKWebView 不能被外部驱动）：在页面里按顺序调用同样的操作，每步读回界面文字 | 自检报告逐步列出结果，任一步失败则打包失败 |
| A3 | **把“只在浏览器里测过”的地方列清楚**。逐个检查应用里依赖平台行为的代码：文件读取、存储、菜单、窗口、声音、剪贴板、拖放打开 SGF。每一处要么在 A1/A2 里覆盖，要么写明为什么不需要 | `docs/QA.md` 有一张对照表，没有空行 |

#### B. 补齐内容（不加功能，只让现有内容完整）

| # | 内容 | 衡量 |
| --- | --- | --- |
| B1 | **补回布局库的定式分支**。v16 的新网络让角部从 1734 降到 1324。做法：<br>• 只放宽角部的取舍阈值（如 `--auto-loss 4`）重建；<br>• 把课程里教的定式线路列为必须展开 | 角部 ≥ 1600；3-4 点高挂、低挂各至少两个书内应手；`adv-joseki-knight#3` 有评估，或者按评估改课 |
| B2 | **名局看点的文字更像人话**。现在每条都是“KataGo 会下 X；损失约 N 目；领先由 A 变为 B”，20 局读起来一样。不加新功能，只改生成规则：<br>• 同一局里不重复同一种句式；<br>• 在“全局最大的转折”处说明这一手之后谁的局面占优；<br>• 坐标同时用“右上”这样的方位 | 每局的看点读起来不重复；仍然只写测得的事实 |
| B3 | **课程和题目在新库下复核一遍**。v16 只检查了书里有的布局与定式步骤，课程里其他用到 KataGo 判断的步骤也用新网络跑一次 `lesson-check` | 有变化的步骤列入 `docs/lesson-audit.md`，按结果修改 |

#### C. 看得见的粗糙处（按 2026-11-18 的走查）

| # | 现状 | 改法 |
| --- | --- | --- |
| C1 | 棋谱页的名局缩略图是 44 px 的终局全图，几百颗子挤在一起，看着像二维码 | 缩略图改显示该局的一个看点局面（子少、有形），或者只画局部 |
| C2 | 练习页第 9 单元（布局的原则）的缩略图几乎是空棋盘，只有三个点 | 每个单元的缩略图取该单元里棋子最有代表性的一步；空棋盘不能做缩略图（加检查） |
| C3 | v16 新加的引擎状态行、测速结果在大字号下挤在一起（CI 上只剩约 14 px 余量） | 精简措辞，不加内容；界面检查的余量至少 40 px |

#### D. 工程（顺带）

- Playwright 1.65.1、ESLint 10.15 等补丁版。
- setup-zig 有 Node 24 版本时升级。
- 在 `docs/` 记下 Intel 版在 `macos-15-intel` 退役（2027 年秋）后的做法。

### 3.3 需要真人或仓库所有者（同 v16）

- **真机验证 V1–V4**：
  - 有 Apple Silicon Mac 的人，在设置 → 引擎里点“测速”，记下数字；
  - 有 Windows 电脑的人做同样的事；
  - 两人都看一眼深浅色切换时标题栏的变化。
- **人的判断 H1–H5**；签名与安装程序 O1–O4；段位题单独立项。

### 3.4 不做（保持产品简单）

- **新的诊断或反馈功能**（“复制诊断信息”等）：已有的“测速”已经够真机验证用。
- **在名局里演示 KataGo 变化**：复盘页已经可以对名局做 KataGo 分析；不另加一条演示路径。
- **新的设置项、新的页面、新的练习模式**。
- **换内置网络**：要重新校准全部难度，收益要等真机速度数据。
- **Zig 0.17**：要等 Native SDK 支持。
- **繁体中文界面、段位题**：属于内容扩张，单独决定。

## 4. 发布前的门槛（v17）

1. 三个平台的打包后自检全部通过，包括 A2 的用户路径；Windows 打包应用里的界面检查（A1）通过。
2. A3 的对照表没有空行。
3. 发布演练一次通过。
4. V1–V4 有真机记录的写进发布说明；没有的，继续写在“已知限制”里。
