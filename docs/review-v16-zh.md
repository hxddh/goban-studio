# Goban Studio v16.0.0 发布后评估与 v17 规划

评估日期：2026-11-15 · 对象：`main` @ `50ba807`（v16.0.0，已发布）· 依据：v16 的执行记录（`docs/review-v15-zh.md` 附录）、仓库所有者反馈的“语言设置不生效”、PR #23 中打包后自检的新检查结果、依赖的上游版本。

## 0. 结论

**v16 发布后发现了一个严重的 macOS 专属缺陷，应先发补丁版。**

- **现象**：仓库所有者反馈“语言设置不生效”。
- **原因**：PR #23 给打包后自检加了语言检查，第一次运行就找到了原因。macOS 的 WebView 读取应用自带文件（`zero://app`）时，返回**状态码 0、没有内容类型，但文件内容完整**（中文字符串 36 KB 全部到达）。应用里每处读取都要求 `r.ok`，于是把这些文件都丢掉了。
- **影响（仅 macOS）**：
  - 设置里换语言后仍是英文；
  - 启动后按需读取的内容（课程、题目、名局）、布局库和落子采样音都读不到；
  - Windows 返回 200，不受影响。
- **为什么到发布后才发现**：
  - 浏览器里一切正常，所有界面检查都在浏览器里跑；
  - 打包后自检只检查引擎和桥接，不碰这些文件；
  - 三个平台的打包 CI 全绿，但没有一项检查读过这些文件。
- **修复**：已在 PR #23。新增 `local-file.js`，接受“ok 或状态 0 且有内容”，四处读取都改用它。打包后自检新增两项必过检查：`languages` 和 `localFiles`。
- **建议**：
  1. 立即发 **v16.0.1**，只含这个修复。
  2. **v17 定为“打包即真实”**：让打包后的应用在 CI 上被真正地使用一遍，而不只是启动并跑引擎。

| | v15 → v16 的判断 | 这次说明了什么 |
| --- | --- | --- |
| 能在 CI 里验证的 | “基本都验证了” | 只验证了**浏览器里**的应用和打包应用的**引擎**；打包应用的界面路径没有被走过 |
| 只有真机能验证的 | Metal、AVX2、断电、标题栏 | 还要加上：macOS 上的整个界面（语言、课程、名局）——现在 CI 的自检能覆盖一部分 |

## 1. 这个缺陷本身

| 项目 | 内容 |
| --- | --- |
| 受影响版本 | v16.0.0 已实测受影响。按需读取内容从 v9 就有，语言文件从 v14 开始单独存放；macOS 外壳从哪个版本开始返回状态 0（例如 v15 的 Native SDK 0.11.1 升级），从这里无法确定 |
| 受影响平台 | macOS（Apple Silicon 和 Intel，同一个 WebView）；Windows 不受影响 |
| 用户看到的 | 换语言无效；打开课程或题目时出现“内容读取失败，重试”（重试也无效）；布局探索没有数据；落子声退回合成音 |
| 修复 | `src/web/js/local-file.js`；`i18n.js`、`content.js`、`explorer-ctl.js`、`audio.js` |
| 防止复发 | 打包后自检必过 `languages`（读文件、按设置的方式切换、检查侧栏）和 `localFiles`（全部内容、布局库、一个音效）；单元测试禁止任何读取再自带 `r.ok` 判断；界面检查覆盖设置里的语言切换 |
| 根本原因 | 外壳对自带文件返回的不是 HTTP 响应。也可以在 Zig 一侧修（返回 200 和内容类型），但那要改 Native SDK 的 macOS 宿主代码；JS 一侧的修复更小，且对两种返回都成立 |

## 3. 规划

### 3.1 v16.0.1（补丁，建议立即发）

只含 PR #23：macOS 上读取应用自带文件的修复，以及新的自检和界面检查。发布演练里，三个平台的打包后自检都必须通过 `languages` 和 `localFiles`。

### 3.2 v17：打包即真实

| 顺序 | 内容 | 衡量 |
| --- | --- | --- |
| 1 | **在打包后的 Windows 应用里跑界面检查**：用 `--remote-debugging-port` 打开 WebView2，用 Playwright 通过 CDP 连接，跑一组核心界面检查（换语言、打开课程和题目、名局、布局探索、下一局、复盘） | PR 的 `package-windows` 里跑过这组检查；macOS 由自检扩展覆盖 |
| 2 | **扩展 macOS 自检**：自检按真实用户的路径走一遍（换语言、打开一课、做一道题、打开一局名局、布局探索），每步读回界面文字 | 自检报告列出每一步的结果 |
| 3 | **诊断报告**：设置 → 关于 → “复制诊断信息”（版本、平台、引擎构建、回退原因、测速结果、最近的读取错误），方便用户反馈问题时附上 | V1、V2、V5 可以通过用户的报告取得真机数据 |
| 4 | **名局看点演示 KataGo 的推荐变化**：检查流程把每个看点的主变化（PV）存下来，复盘里可以一步步演示 | 51 个 KataGo 看点都能演示 |
| 5 | **补回布局库的分支**：放宽一个参数（`--auto-loss` 或 `--share`）重建，或者给常见定式强制展开 | 角部回到约 1700，3-4 点高挂至少两个书内应手 |
| 6 | **工程**：Playwright 1.65.1、ESLint 10.15；setup-zig 有新版本时升级；记录 Intel 版的退役方案 | 全部测试通过 |

### 3.3 需要真人或仓库所有者（同 v16）

- 真机验证 V1–V4；
- 人的判断 H1–H5；
- 签名与安装程序 O1–O4；
- 段位题单独立项。

### 3.4 不做

- **换内置网络**：等诊断报告带来真机速度数据之后再定；
- **Zig 0.17**：要等 Native SDK 支持。

---

## 4. 发布前的门槛（v17）

1. 三个平台的打包后自检都通过，其中包括 `languages`、`localFiles` 和 §3.2 第 2 项的用户路径。
2. Windows 打包应用里的界面检查通过（§3.2 第 1 项）。
3. 发布演练一次通过。
4. V1–V4 至少各有一份真机记录（可以来自诊断报告）；没有的，继续写进“已知限制”。
