# Goban Studio v9: architecture

v9 rebuilds the application layer and the data layer around one loop:
**play a game → see what mattered, on the board → try that moment again →
play the next game**. It keeps the parts that are proven and does not read
any data saved by earlier versions: v9 starts empty.

## What stays (the core)

`rules.js`, `sgf.js` (FF[4] only), `solver.js`, `board.js` (the renderer),
`katago.js`, `engine.js` + `scheduler.js` (lanes, pre-emption), `book.js`,
`capture-ai.js`, `a11y.js`, `audio.js`, `i18n.js`, `update.js`, `host.js`,
the content (`content/*`: course, problems, classics, book), the calibration
data and the KataGo checks of the course. These keep their tests.

## Two spaces

- **Play** (下棋) is where the app opens: the game in progress, or the
  suggested game with one button. It holds the history of your games (the
  old Library, now a list inside Play) and the classics. When a game ends,
  the same board turns into the **post-game review**: one page, one
  analysis (what were the review and the report). Its 1–3 key moments can
  each be **tried again from the position**, on the board, judged by
  KataGo, without leaving the page.
- **Learn** (学棋) is one path chosen for you: the next lesson, problems at
  your level, your own mistakes due for review, the week's focus — as one
  ordered list, not six entries. A quiet catalog (units, problem topics)
  stays reachable for browsing. The beginner bridges of v8 (capture Go,
  the first 9×9 game) live here.

Settings stay a sheet. Onboarding asks language and experience, then opens
Play or Learn.

## One player model

`src/web/js/model/player.js` (pure) is the only place that knows the
player. It replaces the v3 weakness counts, the v5 game records' trend
data, the v6 rating, the v7 plan model and the strength estimate's own
store:

```
profile = {
  v: 9,
  rating: { [size]: { mu, sigma, games, at } },   // Glicko, measured ladder
  history: [{ at, size, rank, pm }],              // for "≈ 12 kyu (±1)"
  games: [{ id, at, size, result, won, phases?, themeLoss? }],  // analysed own games, newest 30
  problems: { [id]: { tries, solved, clean, last, due, streak } },
  mistakes: [{ id, gameId, index, theme, loss, due, ... }],      // drills from own games only
  lessons: { [id]: { done, step, at } },
  week: { start, focus: [theme] } | null,
}
```

Views derived from it, all pure: `estimate(profile)`, `suggestedGame(profile)`,
`learnPath(profile, content, now)`, `focus(profile, now)`, `due(profile, now)`.
Teaching warnings, the post-game review and Learn all read these, so they
never disagree.

## Storage

Desktop: files in the app's data directory (the same root as
`models/`), under `data/`:

```
data/settings.json
data/profile.json
data/games/<id>.json     { id, createdAt, finishedAt, source, sgf, meta, analysis?, review? }
data/current.json        the game in progress
```

Host bridge (Zig, `src/main.zig`): `studio.storeRead {key}`,
`studio.storeWrite {key, b64}` (write to a temp file, then rename),
`studio.storeList {prefix}`, `studio.storeRemove {key}`. Keys are relative
paths of `[a-z0-9_-]` segments separated by `/`, ending in `.json`; nothing
outside `data/` can be named. There is no size limit beyond the disk.

JS: `src/web/js/data/store.js`. At boot `await store.open()` reads
everything into memory (games are small; analysis is stored with its game);
reads are synchronous from memory; writes are debounced per key and
written through the host. The browser preview uses an in-memory store
backed by `localStorage` under one key prefix (development only).

Backups: *Export backup* writes one JSON file of all keys; *Import backup*
replaces them.

## One opponent axis

New game asks for **strength** only, as a measured rank (30 kyu … 7 dan).
`engine.js` maps a rank to an implementation (standard ladder, human-style,
stronger network) from the calibration tables; the player never chooses a
mode. Labels are the measured ranks.

## Removed in v9

- the 40 pro-opening guess drills (the explorer covers openings)
- "guess the next move" in review
- board materials and flat stones (one board look)
- SGF problem-collection import
- the strength chart (the estimate is shown as one number with its ±)
- the "this week" counts
- all v1/v2 keys, migrations, and the pre-v7 SGF coordinate reading
- the separate report page, Today, Practice home, Library page

## Layout

```
src/web/js/            core modules (unchanged names)
src/web/js/data/       store.js, backup.js
src/web/js/model/      player.js, path.js (Learn's order), review-model.js
src/web/js/shell/      app shell, sidebar, onboarding, settings
src/web/js/play/       play view and controller, post-game review, history
src/web/js/learn/      learn path view and controller, lessons, problems
src/web/js/messages/   strings by area: common, shell, play, learn
scripts/tests/         by area: core-*, data-*, model-*, play-*, learn-*
scripts/ui-tests/      by area
```

Strings and tests are organised by area, never by version.
