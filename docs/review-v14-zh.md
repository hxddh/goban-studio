# Goban Studio v14.0.0 评审、上游新版本与 v15 规划

评审日期：2026-11-13 · 对象：`main` @ `11eb097`（v14.0.0）· 方式：只读评审，分三条线并行：

- 代码：核对 v13 评审的问题在 v14 里是否修好，并找新问题。
- 上游：KataGo、网络、Zig、Native SDK、npm 依赖、CI 运行器、WebView 平台能力、签名，都和一手来源核对过。
- 界面：用真实 Chromium 把构建产物逐屏走了一遍（中文浅色 1440×900、中文深色 1200×800）。

标“已复现”的问题有可以运行的最小用例；标“未核实”的上游信息没能在一手来源里确认。

## 0. 结论

**总评：7.4 / 10（v13：7.2）。** v14 的“精致版”目标完成了一半，而且是看不见的那一半。v13 留下的错误结果（B1–B7）基本都修了，代码也整理过：lint 是 0 警告，模块按区域拆分，样式改用 token，语言包按需加载，主 bundle 从 767 KB 降到 692 KB。数据层、SGF、数地、更新链是全项目最扎实的部分。

**看得见的那一半还没做完，这正是“粗糙”的来源。** 问题不在某个 bug，而在三处：

1. **信息密度和层次不够**：页面大多是一列居中的文字行，大屏上两侧留白很多。
2. **下棋这件事本身的反馈太少**：没有提子数，没有形势，没有落子后的“这手怎么样”，对局侧栏下方大片空白。
3. **视觉细节没统一**：深色模式下棋盘发灰发闷；同一个选择在不同地方用两种控件；可以点的文字看起来不像能点。

另外，**引擎和网络还停在 2020 年**。上游早已有更强、更快的方案，这是不改界面也能直接感到“变好了”的一处。

**建议：**
- 先发 **v14.0.1**：修 N1（会让电脑下出一步弱棋），修 N2（今天 `npm test` 必挂）。
- **v15 定为“手感版”**，三条线：
  - **引擎**：换新网络；macOS 用 Metal；Windows 用 AVX2 版本。
  - **对局与复盘的反馈**：形势、提子、每手评价、更好的终局。
  - **视觉系统第二轮**：棋盘材质、深色模式、信息密度、动效。

| 方向 | v13 | v14 | 一句话 |
| --- | --- | --- | --- |
| 围棋核心（规则 / SGF / 求解器 / 调度） | 7.5 | **8.0** | 全死判错已修；SGF 只剩边角问题 |

| 前端代码质量 | 6.0 | **7.0** | 有 lint、模块按区域拆分、token 化；仍是全局 store、求解器在主线程 |

## 3. 为什么“粗糙”：逐屏走查

截图在 1440×900 浅色和 1200×800 深色下拍摄，这里只列问题。

### 3.1 全局

| 现象 | 原因 | 建议 |
| --- | --- | --- |
| 宽窗口下，所有页面都是居中的一列（约 880 px），两侧大片空白 | 为窄窗口设计的单栏布局，宽了也不调整 | 宽度 ≥ 1280 时，今天、练习、棋谱改为“主栏 + 侧栏”两栏，或用卡片网格 |
| 正文 13 px，说明文字 11–12 px，层级只靠粗细区分 | `--t-body` 等 token 是 Mac 原生控件的尺寸，但这里是阅读型内容 | 课文和说明用 14–15 px；标题和正文之间拉开字号差；数字一律用等宽数字 |
| 同一种选择用了两种控件：设置里语言是描边大按钮，主题是分段控件；选中态一个是黑框，一个是白底 | 组件没有收敛成一套 | 单选统一用分段控件或列表；选中态只保留一种 |
| 可以点的文字不像能点：“开始测试”“或者下一盘 13 路”“暂不”是纯文字或下划线 | 次要操作没有专门的样式 | 定一套次级按钮（ghost / tertiary），只给次要导航用下划线 |
| 切换页面、打开面板几乎没有动效；落子有回弹，提子是淡出 | 只有几个 keyframes | 用 View Transitions 做页面切换和“对局 → 复盘”的连续过渡；用 `@starting-style` 做面板和菜单的出现动画（§5.3） |

### 3.2 各屏

- **今天：**
  - 新用户看到的只有一张卡、一行提示和“本周还没有下棋或做题”，上半屏就结束了，下面全是空白。
  - 建议：没有数据时，用一个小预览代替空白，比如今天的一道题，或者一张 9 路棋盘的动画。“本周”改成 7 个点加今日目标。
- **下棋：**
  - 右侧只有对手卡、停一手和悔棋两个按钮、手顺，下面空着。
  - 没有提子数，没有用时，没有形势条，没有“上一手是好是坏”。
  - 坐标只在左边和下边，离棋盘线 50 多 px，和网格的关系很松。
  - 建议：
    - 对手卡里加上提子数和计时。
    - 侧栏底部放一条形势条，教学模式默认打开，可以关掉。
    - 每手棋后加一个可选的小反馈：好 / 缓 / 失误，后台低访问量地算。
    - 坐标贴近网格，四边都可以显示。
- **复盘：**
  - 这是最完整的一屏。
  - 形势曲线锯齿很多，在浏览器预览里是离线估算，真机上用的是 KataGo。
  - 关键手列表只有“第 273 手 · 实战 N13”，看不出亏了多少。
  - 建议：曲线做平滑并标出关键手；列表里每项写出亏了几目，以及“应该下在哪”的小图。
- **练习：**
  - 题目网格（v14 新做的）效果很好。
  - 但上面的课程是 23 行同样的“编号 + 标题 + 0/6”，死活分类也是 8 行纯文字。
  - 建议：每个单元配一张代表局面的缩略图和一条进度条；“基础死活形”的 chip 换成缩略图。
- **棋谱：**
  - 名局是纯文字行。
  - 进行中的那盘（第 8 手）不在“我的棋局”里，只能从今天或下棋页进去，需要确认是否有意如此。
  - 建议：名局行配终局缩略图；进行中的对局在棋谱顶部也显示一行。
- **深色模式：**
  - 棋盘木色压暗以后变成土褐色，和黑子的对比也降了，整体发闷。
  - 建议：棋盘不跟着整体变暗，只降一点亮度、保留暖色饱和度，或者给一个“夜间棋盘”的独立配色。窗口外框跟随主题，用 Native SDK 0.11.1（§5.2）。
- **设置：**
  - 面板在 1440 宽时偏矮偏宽，右侧内容区下方空着。
  - “引擎”页在浏览器预览里只显示“只有桌面版应用可以下载”。真机上的表现，这次没有核实。

- **做得好的：**

  - JS 模块按区域拆分，每个不超过 600 行（有测试强制，例外有清单）。
  - 没有循环依赖；`window.__state` 只在测试浏览器里出现。
  - 测试 585 项，另有 UI 流程、视觉基线和性能预算。

  - **`main.zig` 2406 行，还在变大**（v13 是 2289）。`install.zig` 2251 行，`engine.zig` 1558 行，`net.zig` 1176 行。建议按“桥接命令 / KataGo 进程 / 更新 / 模型下载”拆开。

  - **缺少的测试**：
    - 宿主取消与调度器的交互（N1 就是这里漏的）。
    - 超级劫。
    - 测试里固定日期（N2）。

## 5. 上游新版本：现状与能用上的能力

### 5.1 KataGo 与网络：收益最大的一项

| 组件 | 现在 | 最新 | 能用上的 | 建议 |
| --- | --- | --- | --- | --- |
| KataGo 引擎 | v1.18.1 | v1.18.2（2026-08-30） | 1.18.2 只改了 CUDA，和本应用无关。**1.18.1 已有但没用上的**：① macOS 的 **Metal 后端**（MPSGraph + CoreML 混合，Compiling.md 把它列为 macOS 推荐方案）；② Windows 官方的 **`eigenavx2`** 版本，以及 `onnx-directml`（任意 DX12 显卡） | 版本不用升；**构建方式要换**，见下 |
| 默认网络（内置） | g170-b6c96（2020） | — | 难度等级都是用它校准的。候选是 `lionffen_b6c64_3x3_v10`（2.2 MB，第三方，许可未核实） | 先保留；v15 内评估，换了就要重新校准 |
| “更强分析”网络 | g170e-b15c192（2020，48 MB） | **kata1-b18c384nbt-s9996604416**（98 MB，Elo 13627） | 复盘、提示、数地的质量会明显提升 | **v15 换**。注意下载地址在 `media.katagotraining.org`，而 `models.zig` 只允许 GitHub 地址：要么加白名单，要么镜像到本仓库的 Release，并更新 SHA-256 |
| 拟人对手网络 | b18c384nbt-humanv0 | 同左（仍是唯一的人类 SL 网络） | — | 不变 |
| 更大的网络 | — | b28c512nbt（271 MB），tf3-b11c768（262 MB，Transformer，当前最强） | 只适合 Metal 或 GPU | 有了 Metal 之后，作为“最强”可选项 |

**具体做法：**
1. **Apple Silicon 用 Metal 构建 KataGo，Intel 继续用 Eigen。** 要把 protobuf 和 abseil 静态链接或打包后签名，部署目标为 macOS 13。人类风格和强网络的响应会显著变快，具体倍数待测。
2. **Windows 在运行时检测 AVX2**，有就用 `katago-v1.18.1-eigenavx2-windows-x64`，没有就用现在的 `eigen` 版本。可选再带一个 DirectML 版本做 GPU 加速。
3. **换掉“强”网络**（见上表），同时更正 README 里的网络许可（N13）。

### 5.4 签名

签名是安装体验差的根本原因，v14 仍然没有签名。

- **Windows：**
  - **SignPath Foundation** 对开源项目免费，资格条件未核实。
  - Azure “Trusted Signing” 已更名为 **Artifact Signing**。个人账号只限美国和加拿大，而且要付费订阅。
  - 建议先申请 SignPath。
- **macOS：** 仍是 Developer ID + notarytool。仓库的工作流已经支持，差的只是证书。
