# Goban Studio v14.0.0 评审、上游新版本与 v15 规划

评审日期：2026-11-13 · 对象：`main` @ `11eb097`（v14.0.0）· 方式：只读评审，分三条线并行：

- 代码：核对 v13 评审的问题在 v14 里是否修好，并找新问题。
- 上游：KataGo、网络、Zig、Native SDK、npm 依赖、CI 运行器、WebView 平台能力、签名，都和一手来源核对过。
- 界面：用真实 Chromium 把构建产物逐屏走了一遍（中文浅色 1440×900、中文深色 1200×800）。

标“已复现”的问题有可以运行的最小用例；标“未核实”的上游信息没能在一手来源里确认。

## 0. 结论

**总评：7.4 / 10（v13：7.2）。** v14 的“精致版”目标完成了一半，而且是看不见的那一半。v13 留下的错误结果（B1–B7）基本都修了，代码也整理过：lint 是 0 警告，模块按区域拆分，样式改用 token，语言包按需加载，主 bundle 从 767 KB 降到 692 KB。数据层、SGF、数地、更新链是全项目最扎实的部分。

**看得见的那一半还没做完，这正是“粗糙”的来源。** 问题不在某个 bug，而在四处：

1. **信息密度和层次不够**：页面大多是一列居中的文字行，大屏上两侧留白很多。
2. **下棋这件事本身的反馈太少**：没有提子数，没有形势，没有落子后的“这手怎么样”，对局侧栏下方大片空白。
3. **棋盘不精致**（§3.3）：板面是纯色没有木纹；线宽、星位、坐标按格子线性缩放，9 路和 19 路都不协调；悬停和最后一手的标记粗糙；深色模式发闷。
4. **视觉细节没统一**：深色模式下棋盘发灰发闷；同一个选择在不同地方用两种控件；可以点的文字看起来不像能点。

另外，**引擎和网络还停在 2020 年**。上游早已有更强、更快的方案，这是不改界面也能直接感到“变好了”的一处。

**建议：**
- **决定（2026-11-13）：不单独发 v14.0.1**，N1（会让电脑下出一步弱棋）和其余小修并入 v15.0 一起发。N2 的两处误判已随本评审修正。
- **v15 定为“手感版”**，三条线：
  - **引擎**：换新网络；macOS 用 Metal；Windows 用 AVX2 版本。
  - **对局与复盘的反馈**：形势、提子、每手评价、更好的终局。
  - **视觉系统第二轮**：棋盘材质、深色模式、信息密度、动效。

| 方向 | v13 | v14 | 一句话 |
| --- | --- | --- | --- |
| 围棋核心（规则 / SGF / 求解器 / 调度） | 7.5 | **8.0** | 全死判错已修；SGF 只剩边角问题 |

## 3. 为什么“粗糙”：逐屏走查

截图在 1440×900 浅色和 1200×800 深色下拍摄，这里只列问题。

### 3.1 全局

| 现象 | 原因 | 建议 |
| --- | --- | --- |
| 宽窗口下，所有页面都是居中的一列（约 880 px），两侧大片空白 | 为窄窗口设计的单栏布局，宽了也不调整 | 宽度 ≥ 1280 时，今天、练习、棋谱改为“主栏 + 侧栏”两栏，或用卡片网格 |
| 正文 13 px，说明文字 11–12 px，层级只靠粗细区分 | `--t-body` 等 token 是 Mac 原生控件的尺寸，但这里是阅读型内容 | 课文和说明用 14–15 px；标题和正文之间拉开字号差；数字一律用等宽数字 |
| 同一种选择用了两种控件：设置里语言是描边大按钮，主题是分段控件；选中态一个是黑框，一个是白底 | 组件没有收敛成一套 | 单选统一用分段控件或列表；选中态只保留一种 |
| 可以点的文字不像能点：“开始测试”“或者下一盘 13 路”“暂不”是纯文字或下划线 | 次要操作没有专门的样式 | 定一套次级按钮（ghost / tertiary），只给次要导航用下划线 |
| 切换页面、打开面板几乎没有动效；落子有回弹，提子是淡出 | 只有几个 keyframes | 用 View Transitions 做页面切换和“对局 → 复盘”的连续过渡；用 `@starting-style` 做面板和菜单的出现动画（§5.3） |

### 3.2 各屏

- **今天：**
  - 新用户看到的只有一张卡、一行提示和“本周还没有下棋或做题”，上半屏就结束了，下面全是空白。
  - 建议：没有数据时，用一个小预览代替空白，比如今天的一道题，或者一张 9 路棋盘的动画。“本周”改成 7 个点加今日目标。
- **下棋：**
  - 右侧只有对手卡、停一手和悔棋两个按钮、手顺，下面空着。
  - 没有提子数，没有用时，没有形势条，没有“上一手是好是坏”。
  - 坐标只在左边和下边，离棋盘线 50 多 px，和网格的关系很松。
  - 建议：
    - 对手卡里加上提子数和计时。
    - 侧栏底部放一条形势条，教学模式默认打开，可以关掉。
    - 每手棋后加一个可选的小反馈：好 / 缓 / 失误，后台低访问量地算。
    - 坐标贴近网格，四边都可以显示。
- **复盘：**
  - 这是最完整的一屏。
  - 形势曲线锯齿很多，在浏览器预览里是离线估算，真机上用的是 KataGo。
  - 关键手列表只有“第 273 手 · 实战 N13”，看不出亏了多少。
  - 建议：曲线做平滑并标出关键手；列表里每项写出亏了几目，以及“应该下在哪”的小图。
- **练习：**
  - 题目网格（v14 新做的）效果很好。
  - 但上面的课程是 23 行同样的“编号 + 标题 + 0/6”，死活分类也是 8 行纯文字。
  - 建议：每个单元配一张代表局面的缩略图和一条进度条；“基础死活形”的 chip 换成缩略图。
- **棋谱：**
  - 名局是纯文字行。
  - 进行中的那盘（第 8 手）不在“我的棋局”里，只能从今天或下棋页进去，需要确认是否有意如此。
  - 建议：名局行配终局缩略图；进行中的对局在棋谱顶部也显示一行。
- **深色模式：**
  - 棋盘木色压暗以后变成土褐色，和黑子的对比也降了，整体发闷。
  - 建议：棋盘不跟着整体变暗，只降一点亮度、保留暖色饱和度，或者给一个“夜间棋盘”的独立配色。窗口外框跟随主题，用 Native SDK 0.11.1（§5.2）。
- **设置：**
  - 面板在 1440 宽时偏矮偏宽，右侧内容区下方空着。
  - “引擎”页在浏览器预览里只显示“只有桌面版应用可以下载”。真机上的表现，这次没有核实。

### 3.3 棋盘

棋盘是这个应用里被看得最多的东西，也是“不精致”最集中的地方。以下截图都是 2 倍分辨率（deviceScaleFactor 2）、1440×900 窗口；数值来自 `src/web/js/board.js` 和 `src/web/js/theme.js`。

**结论：** 棋子（程序生成的贴图）和落子、提子动画的底子不错。问题在棋子以外的部分：
- 板面是一块纯色；
- 线宽、星位、留白、坐标都是按格子大小线性缩放的，9 路和 19 路两头都不对；
- 悬停、最后一手、深色模式这几个高频状态没有打磨。

#### 问题

| # | 现象 | 原因（代码） | 建议 |
| --- | --- | --- | --- |
| G1 | **板面没有木纹**，是一块平涂的 `#E4CB9A` 加一圈极淡的暗角，看起来像纸板。函数名叫 `grain()`，实际只画了暗角 | `board.js` `grain()` | 程序生成木纹：直纹（柾目）加细密年轮，用低频噪声扰动，对比度很低（明度差 3–5%）。按尺寸生成一次缓存，现有的缓存机制可以直接用。也可以内置一张 CC0 木纹 webp（约 150–250 KB）。这一项的观感提升最大 |
| G2 | **线宽随格子线性缩放（2% 格宽），两头都不对。** 19 路在 Retina 上只有 1 个设备像素（0.5 CSS px），发虚，压不住棋子；9 路格子大，线又显得粗重 | `lineDev = round(cell × dpr × 0.02)` | 实物棋盘线宽约 1 mm、格宽约 22 mm，约 4.5%，但屏幕上不宜照搬。建议线宽 = clamp(1 CSS px, 格宽 × 3%, 2 CSS px)，边线是内线的 2 倍；线色比现在略浅、实色不透明，避免与暗角叠出深浅不匀 |
| G3 | **星位太小。** 19 路上半径约 2.4 px，几乎看不见 | `max(1.5, cell × 0.065)` | 半径约格宽 × 0.1，下限 2.5 px |
| G4 | **9 路留白过大，坐标离网格太远。**（原型实测修正：坐标离网格远主要因为它必须让在边上棋子之外，9 路半颗棋子就有约 40 px；改公式只能收回 5–8 px。真正的改进要靠更小的坐标字号和“四边坐标”选项，收益比原先估计的小） 9 路四周木边约 75 px，坐标离网格约 58 px，贴着木板外缘，和它标注的那条线看不出关系；19 路坐标又挤在约 30 px 内 | `marginCells = min(1.25, 0.5 + 34/cell)`；`gap = min(0.8 × cell, 0.5 × cell + 18)` | 留白 = 半颗棋子 + 固定坐标带（约 22 px），不再按格数算；坐标放在“半颗棋子外 8–10 px”的固定位置。用等宽数字，字号 11–12 px，字重 500，透明度约 55%。设置里提供“四边显示坐标” |
| G5 | **悬停预览是一块浑浊的褐色圆斑。** 黑子贴图以 42% 透明度叠在木色上，得到一种发脏的土褐色，没有边缘，不像一颗棋子 | `alpha: 0.42, shadow: false` | 黑子 55–60% 透明度，加一圈细的实色外缘；白子 70%。或者只画一个空心圆（落子提示，不是棋子）。两种都比现在的半透明圆斑干净 |
| G6 | **最后一手的标记偏重。** 白子上的深灰圆环线宽 5% 格宽、透明度 0.8，压过了棋子本身 | `lastMarkOf`、`onWhite` | 圆环线宽降到约 3.5% 格宽、半径约 0.22 格；或改为实心小圆点或小三角，用强调色（最后一手是需要一眼看到的信号）。两种方案都做出来，在 9 路和 19 路上比较 |
| G7 | **深色模式下棋盘发闷**：板面压成 `#927D58`（饱和度和明度都降了），白子再盖一层 14% 的暗色，黑子加一圈浅色描边，像塑料 | `STANDARD_DARK` | 深色模式里变暗的是房间，不是棋盘：板面只降 10–15% 明度、保留饱和度；白子不压暗，黑子不描边，靠棋盘与背景的对比把它们托出来。另外可以提供“夜间棋盘”（深色木，例如胡桃木）作为单独的板材选项 |
| G8 | **棋盘像一张卡片**：圆角加悬浮阴影，没有厚度 | `.board-frame` 的 `border-radius` 和 `--shadow-board` | 直角（最多 2 px 圆角）；边缘画 1–2 px 的木口亮边或暗边，表现出厚度；阴影改为贴近桌面的短阴影 |
| G9 | **落子动画是 UI 式的弹出**：棋子从 0.82 倍缩放回弹到 1（easeOutBack），像按钮出现，不像棋子落下 | `PLACE_MS = 140`，`easeOutBack` | 改为“落下”：棋子不缩放，阴影从大而淡收到小而实（约 120 ms），可选 1–2 px 的位移。提子的“飘向棋罐”动画保留 |
| G10 | **白子贴图的贝壳纹在 19 路小尺寸下成了噪点**；黑子在小尺寸下高光看不出来，像平面圆片 | `scripts/assets/stones.mjs` | 白子纹理对比度按显示尺寸衰减，或者针对小尺寸单独生成一套贴图；黑子加一点哑光的边缘反光（rim light）。另外贴图可按点位随机旋转角度，让同一种贴图看起来不重复 |
| G11 | 正方形网格。实物棋盘约 22 × 23.7 mm，纵向略长，坐着看时显得是正方形 | 网格横竖等距 | 可选，不必默认：“传统比例”开关，纵向 × 1.07 |
| G12 | 题目缩略图上，目标棋子用“白子中间一个黑点”表示，像靶心，第一次看不懂；缩略图的取景大小也不统一 | `thumb.js` | 目标棋子改用三角或方块标记，与 SGF 的常用记号一致；同一分组里的缩略图统一取景比例 |
| G13 | 落子声和提子声是物理建模合成的（`scripts/assets/sounds.mjs`），这次没能试听，未评估 | — | 在真机上和真实录音（CC0 的榧木棋盘、蛤碁石素材）做一次盲听对比，再决定是否换 |

#### 建议的做法

1. **先定一份“棋盘规格”文档**，补充 `docs/design.md` §5。用格宽的函数，写清线宽、边线、星位、棋子直径（0.95 格）、阴影、留白、坐标位置和字号、最后一手、悬停、候选点、领地标记的数值。9 / 13 / 19 路各给一张示意图。现在这些数值散落在 `board.js` 的各个绘制分支里，各自按自己的比例缩放，这正是不协调的原因。
2. **按收益排序**：G1 木纹 → G2 + G3 线和星位 → G4 留白与坐标 → G5 + G6 悬停与最后一手 → G7 深色 → G8 + G9 厚度与落子手感 → G10 棋子贴图。前四项改的都是 `board.js` 和 `theme.js` 里的数值和一个木纹生成函数，量不大。
3. **验收方式**：视觉基线里加 9 / 13 / 19 路 × 浅色 / 深色 × 1 倍 / 2 倍的棋盘特写（只截 canvas），并且找一位下棋的人对比真实棋盘或主流对弈软件，逐项打分。
