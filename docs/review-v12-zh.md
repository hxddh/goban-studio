# Goban Studio v12.0.0 深度评审与 v13 规划

评审日期：2026-11-08 · 对象：`main` @ `21171d1`（v12.0.0）· 方式：只读评审，五个方向并行深读源码，并在本地复现关键问题。

## 0. 结论

**总评：6.8 / 10。** 工程底子在同类个人桌面应用里明显偏上：题目和课程由求解器机器证明，发布流水线在三种真机上做自检、更新回滚测试和截图巡检，文档对自身局限诚实。主要问题有三块：

1. **正确性边缘有真 bug**，其中一个会让比赛结果判反（§2.1）。
2. **信任边界和数据安全**有几处缺口：桥接接口能读写任意文件；启动时读盘失败会被当成新用户；进行中的对局可能被静默替换。
3. **产品方向反复，缺少真人验证。** 8 天内发了 11 个大版本（v2→v12），空间数量从 4 改到 2 又改回 4，v11 的新内容在 v12 撤回。usability.md 里写的真人测试、母语审校、读屏实测一项都还没做。

**建议：v13 不再改信息架构，定为“可信版”（Trustworthy），**先修正确性、安全和数据安全，把真人验证设为发布闸门，再做有节制的学习系统升级。

| 方向 | 评分 | 一句话 |
| --- | --- | --- |
| 原生壳层（Zig / 更新器 / KataGo 进程） | 7.0 | 进程生命周期和更新回滚做得细；桥接文件权限过宽，ReleaseFast，KataGo 无超时 |
| 围棋核心（规则 / SGF / 求解器 / 引擎调度） | 7.0 | 合法性、劫、双活、求解器扎实；数地有判反 bug，SGF 对真实世界输入不够健壮 |
| 前端与 UX（状态 / 存储 / 无障碍） | 7.0 | 存储写链与取消机制出色；启动失败、恢复备份、替换对局时有丢数据风险 |
| 内容与学习模型 | 6.5 | 内容全部经过验证；难度分级以求解器为准而非人，定级会严重高估，题库窄、上限低 |
| 工程流程（CI / 发布 / 供应链） | 6.5 | 发布闸门严格；PR 不编译 Zig，tag 不绑定构建提交，部分下载未锁哈希 |

验证结果（本地）：`npm test` 305 项全过（57 s）；`npm run ui-test` 74 项全过（四语言、无障碍审计、性能预算、视觉基线）；`release-check` 通过（18 单元 · 82 课 · 543 题 · 20 名局）。冷启动首屏中位数 213 ms。

## 1. 做得好的（v13 必须保住）

- **可证明的内容。** 每道题由 `solver.js` 证明：1–3 个正解、终局胜势、对称/换色去重、真实棋盘规则（可回提、扑、填眼）、关键子封闭。双活、劫、收官计数都有严格判定。课程四语言逐步验证，另有 KataGo 审计。
- **发布流水线。** 三个平台各在原生 CPU 上构建（Intel 不交叉编译）。打包后的应用在真实 WebView 里跑 KataGo 自检，在真机上测更新器的替换、回滚和只读回退，并截图巡检。全部变绿才打 tag。有 rehearse 模式。签名状态如实写进发布说明。
- **更新器在其信任模型内做得扎实。** 下载 URL 前缀固定，重定向只允许精确主机。SHA-256 在流上和落盘后各校验一次。zip 条目先校验再解压，再查 CPU 架构和 bundle id。助手脚本用 argv 传参，不存在注入；能回滚，也会迁移 WebView2 profile。
- **存储层。** 每个键一条写链，新写覆盖旧写。分块写入后由宿主原子 rename。失败重试并只提示一次。键名两端都做白名单校验。
- **引擎调度。** 统一用 AbortSignal，分 lane 抢占并重新排队，`gen` / `lineKey` 防止旧结果落到新局面。
- **无障碍投入。** 棋盘可用键盘光标操作并朗读，有 aria-live 批量播报、模态框焦点陷阱与归还、大字模式，Canvas 动画遵守 reduced-motion。
- **诚实的文档。** `strength.md`、`plan.md` 的“它不知道什么”、两份 audit 都主动写明局限。

## 2. 关键问题（按严重度）

### 2.1 Critical：会给出错误结果或丢数据

| # | 问题 | 位置 | 场景 | 状态 |
| --- | --- | --- | --- | --- |
| C1 | **数地判反。** 空域只要碰到四条边就算单官，即使四周只有一种颜色 | `src/web/js/rules.js:245`（`edges.size < 4`） | 9×9：白在左上角活一小块，黑外势围住其余全部。`territoryMap` 给黑 **0 目**，给白 4 目，`score()` 判白胜。这正是初学者对弱级别时最常见的终局 | **已本地复现** |
| C2 | **启动读盘失败会被当成新用户，随后覆盖真实数据** | `data/store.js:272-282`，`controller.js:61-78` | `list` 或某个核心键读失败后，`open()` 仍然正常返回。boot 用默认设置和空档案并弹出引导，用户点完后 `settings.json` / `profile.json` / `current.json` 被覆盖 | 代码确认 |
| C3 | **进行中的对局会被静默替换** | `review-ctl.js:974 playFromHere`，`explorer-ctl.js:339`，`play-ctl.js:245 newGame` | 下到 120 手时去棋库点名局的“从这里下”，原对局直接消失（未完成的对局不进历史），无法撤销 | 代码确认 |
| C4 | **桥接接口可读写任意路径，发布版仍允许开发源 `127.0.0.1:5173`** | `main.zig:13, 577-613`，`app.zon:26`，`store.zig:310-353` | 一处 XSS（例如 SGF 注释渲染），或本机有进程监听 5173，就能以用户身份读写任意文件（例如写入 LaunchAgents 实现持久化） | 代码确认 |

### 2.2 High

- **恢复备份不是原子操作，也没有退路**（`backup.js:46`）。写入中途失败时，内存里是旧状态、磁盘上是备份，下一次写入会把两者混在一起。恢复前不做快照，`checkBackup` 也不检查大小。
- **导出可能“假成功”**（`play-ctl.js:826-848`、`review-ctl.js:998`）。原生写入失败时退回 `<a download>`，这在 WKWebView/WebView2 里通常什么都不做，界面却显示“已导出”。备份导出时影响最大。
- **ReleaseFast 发布**（`build-*.yml`、`build.zig:47`）。壳层解析不可信的 JSON 和 KataGo 输出，大量 `@memcpy` / `@intCast`，越界在这种模式下会变成静默内存破坏。应改为 ReleaseSafe，代价可以忽略（热点在 KataGo 里）。
- **KataGo 输出没有超时，同步 API 会冻结 UI**（`engine.zig:356,480`，`main.zig:657-686`）。`readReply` 无限阻塞，同步路径在 UI 线程上取排他锁，还接受任意 `kata-set-param`。前端已经全面走异步，同步 API 约 250 行可以整段删掉。
- **SGF 健壮性。** 第二个节点里的 AB/AW 导入和导出时都会丢（`sgf.js:335-342`，已复现）。`SZ` 不是 9/13/19 时静默按 19 处理。非法坐标被当成 pass。`HA` 没有 `AB` 时让子放两遍。忽略 `CA`：GBK、Shift_JIS、EUC-KR 棋谱会乱码，而中日韩档案正是目标用户的主要来源。深度递归，上万节点会栈溢出，加载复杂度 O(n²)。
- **定级严重高估（学习层面最严重的问题）。** 难度分级来自求解器搜索量的五分位（`problems.js:496`），与人的难度无关。`capture-ladder-00`（单纯征子）是 5 级；`capture-basic-01`（打吃提一子）是 3 级，而它的孪生题是 1 级。`PLACEMENT_RANK` 把 5 级映射为约 4 级位（`player.js:1059`）。会读征子的 20 级玩家可能全对通过定级，被送进 5k–1d 课程，而且定级题序是确定的，一道生死题都没出。
- **发布 tag 未绑定构建提交**（`release.yml:162`）。`gh release create` 没带 `--target`，tag 在发布那一刻按默认分支 HEAD 创建，构建约 100 分钟期间 main 一旦前进，tag 就和二进制对不上。
- **PR 不编译也不测 Zig**（`checks.yml`）。34 个 Zig 单测（更新器 URL 白名单、SHA 解析、zip 校验）只在手动构建和发布时才跑。

### 2.3 Medium

- 更新包没有签名：SHA256SUMS 和安装包来自同一个 release，掌握 GitHub token 的人就掌握了自动更新。另外可以降级（`main.zig:1218` 接受页面传来的任意 tag），助手脚本启动失败时应用已经退出且无法恢复，两个助手还可能并发执行。
- 求解器把预算耗尽时的非精确结果写入置换表并复用（`solver.js:895-928`），可能把学习者的正确变着判为“被反驳”。
- 一个含控制字符的打开文件路径会卡死后续所有“打开文件”，直到重启（`main.zig:1608`）。
- Windows 版 KataGo 下载没有哈希校验（`build-windows.yml:65`）。提交进仓库的模型 `engine/model/model.txt.gz` 没有记录哈希。KataGo 源码按 tag 而不是 commit 检出。
- 构建 job 一律 `contents: write`，`npx --yes` 和 `npm install -g` 绕过 lockfile，签名 secrets 作用于整个 job。actions 按 tag 而不是 SHA 固定。
- 计时对局每 250 ms 重渲染整个应用，并重绘 Canvas。
- 退出时只在 `pagehide` 上做一次异步 flush，最后约 300 ms 的写入（例如对局结果）可能丢失。
- 启动时串行读完所有文件。每盘分析过的 19×19 对局约存 0.5 MB（每手 361 点的 ownership），库一大首屏就会明显变慢。
- 复习会鼓励背答案：题目不做旋转、镜像或换色。间隔是固定的 1-3-7-21 天，题目永不退休。一次误点就重置。
- 备份要求严格的 `v === 9`，没有迁移框架，以后每次格式变更都会把旧数据困住。

### 2.4 Low（摘要）

- i18n：回退语言是 `zh`，英文用户缺键时会看到中文。没有复数处理。CJK 文本里用 ASCII 冒号拼接。韩语助词写死。
- `minify:false`，主 bundle 1.06 MB，压缩后约减半。消息表 215 KB 在启动时全部解析。
- 危险确认框的默认焦点在危险按钮上。`--text-3` 对比度约 3.3:1，不达 WCAG AA。没有 `forced-colors` 样式。
- v9→v12 反复改动留下的命名债：内部 id 仍是 `"learn"`；`SPACES` 定义了两次；文件头注释还写着“两个空间”；存在循环依赖 `play-ctl ↔ review-ctl`。
- 文档漂移：`docs/QA.md` 仍写“28 checks / 300 drills / 只有日本规则”。Node 版本 22/24/26 混用，`engines` 也没强制。
- 约 30 个测试是对源码做 grep（`shell-release.mjs` 有 55 处 `assert.match`），重构时容易误报。
- 原生代码重复：`runner.zig` 里四个几乎一样的 `run*`；四套 JSON 写入器，转义规则各不相同；`main.zig` 1779 行。

## 3. 过程层面的观察

1. **版本号已经失去意义。** 8 天 11 个大版本，每个都是一次 squash 的巨型提交（v5 +19k 行，v9 +16k/−17k 行）。bisect、blame 和“破坏性变更”的语义都没了。
2. **方向反复的代价。** 4→2→4 空间、v11 加内容 / v12 撤回，都是在没有任何真人数据的情况下做的决定。每次重构都留下命名债和耦合。
3. **验证缺口始终没补。** 真人可用性测试（5 名新手 + 5 名级位玩家）、强棋手审课、中日韩母语审校、VoiceOver/NVDA 实测，从 v3 起每份发布说明都列为“已知限制”。

## 4. v13 大版本内容建议：“可信版”

**原则：** 不动信息架构（四个空间保持不变）。v13.0 只修正确性、安全和数据安全；v13.x 用小版本推进学习系统。每一项改动都带回归测试。

### 4.1 v13.0 必须完成（发布阻断项）

**A. 结果正确**
- [ ] 修复 C1 数地：终局（死子已移除）时取消四边规则。如果需要“近乎空盘”的保护，改用“区域内无对方棋子且占比”之类的条件。补回归测试“角上活一块、其余全属一方”，三种规则都测。
- [ ] SGF：第二节点的 setup 应用到根；中盘的 AB/AW/AE 真正落子；支持 2–25 路或明确报错；非法坐标给出警告；`HA` 无 `AB` 时不预置让子；`HA[0]`；按 `CA` 解码（GBK、Shift_JIS、EUC-KR）；改为非递归解析并去掉 O(n²)。为每一项补测试。
- [ ] 求解器：预算耗尽的结果不进缓存，`reply()` / `status()` 把非精确结果视为“未定”。
- [ ] 提示和数子加 `gen` 校验，引擎失败时回退到离线引擎或提供“重试”。

**B. 数据不丢**
- [ ] 启动读盘失败时进入只读/重试状态，阻止写入对应键；无法解析的文件改名为 `*.bad.json` 留存。
- [ ] 替换进行中的对局前先确认，或自动把它存入棋库并标为“未完成”。
- [ ] 恢复备份：先自动做快照，预先检查大小，结束后无论成败都重新加载。
- [ ] 原生环境下导出失败要报错，不再退回 `<a download>`。
- [ ] 宿主在关窗前要求页面 flush（原生退出钩子）。
- [ ] 建立数据迁移框架（`v` 递增和逐版本迁移函数），不再用 `v === 9` 一刀切。

**C. 安全**
- [ ] 发布版移除 `127.0.0.1:5173`。`read/writeTextFile` 只接受原生侧签发的路径（文件对话框结果或打开文件事件的能力令牌），并限制扩展名。
- [ ] 改用 ReleaseSafe 打包。
- [ ] KataGo 每个请求设截止时间加看门狗：超时就 kill，再走已有的重启路径。删除同步 API（约 250 行）。
- [ ] 用 minisign/Ed25519 签名 `SHA256SUMS`，公钥内嵌进应用（不依赖苹果或微软证书）。拒绝降级。助手脚本写“已启动”标记后应用才退出。加单实例锁。

**D. 流水线**
- [ ] `checks.yml` 增加 `zig build test`（至少在改动 `src/**.zig` 的 PR 上跑）。
- [ ] `release.yml` 加 `--target "$GITHUB_SHA"`，并校验 tag 与 `package.json` 版本一致。
- [ ] Windows KataGo 加 SHA-256 校验，模型哈希写进 `release-check`，KataGo 按 commit SHA 检出。
- [ ] 默认 `permissions: contents: read`，只给上传/发布步骤 write。actions 按 SHA 固定。secrets 只作用于签名步骤。Native SDK CLI 放进 devDependencies。启用 Dependabot。
- [ ] UI 测试固定容器镜像；缺少基线时让 CI 失败；性能预算取 N 次中位数。

**E. 真人验证（作为闸门，不再只是“已知限制”）**
- [ ] 按 `docs/usability.md` 的协议做 5+5 人测试，过 SUS ≥ 75 / SEQ ≥ 5.5 线。
- [ ] VoiceOver（macOS）与 NVDA（Windows）各一次实测。
- [ ] 用 `docs/l10n/strings.csv` 请中日韩母语者审校，统一术语（例如日语 虎の口/カケツギ、呼吸点/ダメ，英语 Flower six/rabbity six）。

### 4.2 v13.1：学习系统校准

- **定级重做。** 自适应 10–12 题、随机抽题、主题混合，至少 3 道生死题，同一级别需要解对两题。在难度分级以人为准之前，定级上限约为 10 级位。
- **难度重标。** 先加入读秒深度和局面特征（征子长度应算“易”）。再用人工小组排序，或可选的匿名本地导出数据，拟合题目和玩家的 Elo。
- **复习升级。** 复习时随机做对称变换和换色。改用 FSRS 式调度，按分级回忆打分，掌握后退休。加“确认落子”或误点撤销。设积压上限并处理逾期。
- **棋力估计的第二通道。** 用 KataGo human 模型在各段位 profile 下计算玩家落子的似然（类似 KaTrain / AI Sensei 的做法）。哪怕只收集少量真人对局，也能用来锚定刻度。

### 4.3 v13.2：内容扩展（质量优先，吸取 v11 的教训）

- **题库：** 加入白先、边上和中腹的战斗，从名局和玩家自己分析过的对局里截取实战局面，补长读秒的段位题、手筋族（挖、夹、乌龟不出头、破眼、滚打包收、渡），以及按大、中、小分级的官子。每道新题必须经过强棋手审阅后才能入库。
- **新单元：** 劫争（劫材、缓气劫、何时开劫）、形势判断与数目、官子分级（含出入计算）、布局框架（中国流、三连星、小林流）与方向、与定式图谱联动的定式扩展、让子棋策略、**数子法**（中文用户默认）。
- **修订：** 重建玩具棋盘式的官子单元；用当前网络重跑课程审计；更正“双先最优先”等过度概括（`course-intermediate.js:1502`）；核实名局里的事实性陈述（例如 `classics.js:348` 写的李昌镐首个世界冠军）。

### 4.4 贯穿 v13 的工程治理

- **语义化版本：** 改数据格式或做不兼容变更才升 major；功能升 minor；修复升 patch。
- **保留可 bisect 的历史：** 一个功能一个 PR，不再把整个大版本压成一个提交。
- **性能：** 存储的分析里去掉 ownership（或只保留关键手）；启动时只读元数据，对局文件懒加载；时钟只重渲染自身；bundle 开启 minify。
- **代码：** 把 `play.jsx` 拆成 `review.jsx`；用一张表派生 `main.zig` 的 handler 和 policy；合并四套 JSON 写入器和 `runner.zig` 里的 `run*`；清理“learn / 两空间”的残留命名；源码 grep 式测试改为行为测试。
- **文档：** 更新 `QA.md`；统一 Node 版本并加 `.nvmrc` 和 `engine-strict`；补 `SECURITY.md` 和 `CONTRIBUTING.md`；Windows 签名转向 Azure Trusted Signing（`docs/signing.md` 已经指出 `.pfx` 不再可用）。

### 4.5 v13 不做的事

- 不再调整空间和导航结构。
- 不加入未经强棋手审阅的生成题目或引擎生成的点评。
- 不追求题量数字，不追求新入口。
