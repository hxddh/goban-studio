# Goban Studio v13.0.0 深度评审与 v14 规划

评审日期：2026-11-11 · 对象：`main` @ `f4c8739`（v13.0.0）· 方式：只读评审。四个方向并行深读源码（围棋核心、原生壳层与流水线、前端与交互、内容与学习模型），另用真实 Chromium 把构建产物从首次启动到复盘逐屏走了一遍（中文浅色 1440×900、英文深色 1200×800、新手路径、窄窗口）。下文标“已复现”的问题都有可运行的最小用例。

## 0. 结论

**总评：7.2 / 10（v12：6.8）。** v13 的“可信”目标基本达成：上一份评审列出的 4 个 Critical 和绝大多数 High 都已修复，并经得住针对性的攻击测试。数地、SGF、求解器、数据安全和桥接权限这几块，现在是整个项目最扎实的部分。

剩下的问题换了性质。v12 的问题是“会算错、会丢数据”，v13 的问题是**“能用，但不精致”**：

1. **有一个天天会碰到的功能是坏的。** 棋谱里的“重命名”一点就抛异常，从 v7 坏到现在，没有任何测试覆盖（§2.1）。
2. **仍有 6 个会给出错误结论的问题**：一方棋子全死时判错胜负、中国流教错了、做题水平会被复习“刷高”、复习越积越多等（§2.1）。
3. **安装和首次启动是全流程里最差的一段。** 没签名，Windows 是裸 zip，macOS 15 上的首启说明已经失效，Windows 数据位置的文档是错的。
4. **界面克制但单调，细节没打磨。** 题目列表是一墙相同的文字，今日路径连着四行“征子”，设置里有两个“棋力”，13 路棋盘被写成“中盘”。
5. **代码能跑但不优雅。** 没有 lint 和类型检查（重命名的 bug 用 `no-undef` 一秒就能查出），两个千行控制器，样式表三分之二是历次版本叠上去的补丁。

**建议：v14 定为“精致版”，主题正是“精致、优雅、易用”。** 不加新空间，不追题量。先发一个 v13.0.1 把 §2.1 的错误修掉，然后用 v14 做三件事：把安装到第一盘棋的路铺平（易用），把每一屏的细节和文案磨一遍（精致），把代码和设计系统收拾到能长期维护（优雅）。

| 方向 | v12 | v13 | 一句话 |
| --- | --- | --- | --- |
| 围棋核心（规则 / SGF / 求解器 / 引擎调度） | 7.0 | **7.5** | v13 的修复全部成立；全死判错和离线引擎不会停手仍在 |
| 原生壳层（Zig / 更新器 / KataGo 进程） | 7.0 | **7.0** | v12 的安全清单已关闭；没有单实例保护，更新签名有重放缺口 |
| 工程流程（CI / 发布 / 供应链） | 6.5 | **6.0** | 卫生很好，但发布的是未签名的裸包，最大的第三方依赖没锁，平台代码不进 PR |
| 交互与 UX | 7.0（合并） | **6.5** | 流程短而安静；重命名坏了，提示条不可操作，多处点了没反应 |
| 前端代码质量 | 7.0（合并） | **6.0** | 数据层可信；没有 lint 和类型，千行控制器，样式表是堆出来的 |

验证结果（本地，Node 24）：`npm test` 418 项全过；`npm run ui-test` 88 项全过（四语言、无障碍审计、性能预算、视觉基线）；`release-check` 通过（23 单元 · 104 课 · 543 题 · 20 名局）。主 bundle 767 KB。

工程流程降了半分不是因为退步，而是这次把“用户拿到的安装包”也算了进去。

### 2.2 High / Medium：不丢数据，但明显不顺

**安装与首启**

- **macOS 15 上的首启说明已经失效。** 包内 README、发布说明和仓库 README 都写“右键 → 打开”。macOS 15 取消了这条路，要去“系统设置 → 隐私与安全性 → 仍要打开”。备用的 `xattr` 命令路径只对 DMG 用户成立，zip 里的应用叫 `GobanStudio.app`。
- **Windows 数据位置的文档是错的。** `packaging/README-Windows.txt:27-29` 说数据在 `bin\goban-studio.exe.WebView2`，并建议手动更新时复制这个文件夹。v9 起数据就在应用数据目录里了，照做什么也备份不到。应用里也没有“打开数据文件夹”。
- **没有单实例保护。** 双击两次，或应用开着时双击一个 `.sgf`，会起第二个进程，两个进程各自重写同一组文件，后写的赢。这正是 v13 想消灭的那类问题。
- **Windows 是裸 zip**：没有快捷方式、开始菜单、卸载、WebView2 检查；`.sgf` 关联要手敲一条 PowerShell。
- **DMG 里没有“应用程序”替身**，用户会直接从映像里运行，应用内更新随即不可用。
- **更新和模型下载不走系统代理，只认 GitHub。** 对中文用户这是最常见的失败原因；约 100 MB 的更新包不能续传，停 60 秒就放弃。

**对局与复盘**

- **离线引擎不会停手，还会填自己的眼**（`ai.js:95, 226`，已复现）。终局后黑停一手，白往自己的空里连下 18 手才停，最后只剩一口气。浏览器预览的 13/19 路、带让子的 9 路，以及 v13 新加的“KataGo 没出手就由离线引擎下”都会走到这里。
- **复盘里的变化是“碰巧”保存的。** 试下不会标记修改，关掉就没了；之后只要写一句注释，所有误点出来的分支都会一起存下。删除变化和清除标记没有确认也没有撤销。
- **误触会切模式。** 对局中按 ← 进入复盘并取消电脑的着手；复盘里误点棋盘就开了分支，之后 ←/→ 不再走主线。
- **确认数目后无法重开。** 标错一块死子并点了确认，对局已经计分并进入复盘。
- **未下完的对局会堆满棋谱，而且只能续下不能看。** 每次下一手就开新局都多一行，没有筛选也没有清理。

**反馈**

- **没有错误边界。** 任何渲染异常都会留下半更新的画面，没有任何提示；B1 就是现成的例子。
- **提示条的语气是反的，而且不能点。** “导出失败”这类错误没有样式，看起来像普通消息；“这里不能下”却是红色。深色模式下红底白字约 2.6:1。提示条 `pointer-events: none`，所以不能关，也放不了“撤销”。85 个字符的句子只显示 2.6 秒。
- **点了没反应。** 课程或名局内容懒加载失败时点击无效；打开大棋谱没有加载状态；清除数据失败没有说明。

**SGF 的边角**

- 合集文件只导入第一局，不提示（千题合集只进来“第 1 题”）。
- FF[3] 的长属性名（`AddBlack`、`SiZe`）读成空的 19 路棋盘，不提示。
- 没有 `CA` 的 GBK、Shift_JIS 老棋谱仍是乱码，而老档案恰恰常常不写 `CA`。
- `KM[375]`（野狐格式）读成贴 375 目；`DT[1846]` 导出时变成今天的日期。

### 2.3 Medium：更新器与流水线

- **更新签名不绑定版本。** 签的只是 `SHA256SUMS` 的字节。控制发布的人可以把 v13 的包、校验和与签名原样挂到 `v99.0.0` 下，所有已签名的应用都会接受，等于降级或冻结。
- **签名密钥暴露给演练。** `release.yml` 的签名步骤没有排除 `rehearse=true`，也没有受保护的 environment；任何能推分支并触发工作流的人都能用真密钥签名。密钥要防的正是这种人。
- **Native SDK 没锁。** `npm install -g @native-sdk/cli@<输入的版本>` 没有 lockfile 和完整性哈希，postinstall 还会从 GitHub 下一个二进制。它最终变成发出去的可执行文件。v12 评审的这一条没做。
- **`upload` 侧门。** 两个构建工作流可以从任意 ref 向已发布的 tag 覆盖上传，`SHA256SUMS` 不会重算，一次误操作会让该平台的应用内更新全部校验失败。
- **平台专有代码没有自动 CI。** `macos_open.m`、`win_close.zig` 的 Windows 部分和两个更新助手只在手动构建或发布时编译，而发布说明承认它们没在真机上试过。
- **Windows 更新助手启动方式脆弱**：未签名程序拉起隐藏的 `powershell -ExecutionPolicy Bypass`，等 5 秒；替换期间屏幕上什么都没有。

### 2.5 优雅度：代码与设计系统

- **没有任何静态检查。** 没有 ESLint、Prettier、`jsconfig`，没有一处 `@param`。B1 是 `no-undef` 级别的错误。
- **一个全局可变 store，只在 `<App>` 订阅一次。** 每次 `update()` 都重渲染整棵树并重绘棋盘，时钟是唯一的例外。
- **`controller.js` 把九个模块 `export *` 成约 290 个函数的平面命名空间**，视图里用到 170 个不同的 `C.*`。
- **两个千行控制器。** `play-ctl.js`（1033 行）混着对局状态、引擎回合、指导棋、计时、数目、计分和导出；`review-ctl.js`（1015 行）同样。`model/player.js` 1485 行，86 个导出。
- **分层倒置。** `data/pack.js` 引用 `app/summary.js`；`play/` 和 `learn/` 引用 `app/` 30 处；棋谱页写在 `play/home.jsx` 里。
- **版本号渗进了代码。** 空间 id 仍是 `learn`（界面叫“练习”）；消息文件有三套划分方式并存（113 KB 的单体、按区域、按版本的 `v13-*.js`）；36 个 `v13.*` 字符串键；约 450 处“vN”考古注释。
- **样式表：令牌是真的，上层是堆的。** 颜色几乎全走令牌；间距只有 56%，圆角 52%，阴影 35%，z-index 0%。文件头还写着“v4”，响应式块后面追加了约 200 行 v5/v6/v9 补丁，`.btn` 有 14 组规则。

### 小结

§4.0 的九项里八项已做，B3 做了一半。§4.1 和 §4.2 里凡是只靠代码就能完成的，大多已做；没做的集中在三类：要所有者出面的（证书、签名密钥、安装包），要真人参与的（§4.4 全部，以及依赖强棋手的内容扩充），和 §4.3 B–D 的结构重构。评审对 v14 的定位是“精致、易用”要由真人来验证，这一点 v14 没有做到，发布说明如实写了。
