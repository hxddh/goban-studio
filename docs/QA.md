# Verification

This file records what was exercised on the Linux orb that produced the
current checkout. It is deliberately separate from the product claims in the
README.

## Automated

`npm test` — 22 checks:

- default 19×19 board and 7.5 komi
- coordinates and point formatting
- undo discards a leaf instead of leaving a hidden branch
- alternating turns, occupied/outside rejection
- capture and prisoner accounting
- suicide
- simple ko
- Chinese area scoring and Japanese territory scoring
- dead-stone removal
- sparse-board territory guard
- SGF export/import with setup stones, comments, result and variations
- SGF import with pass, setup, comments and `YYYY-MM-DD` dates
- invalid SGF rejection
- every UI string present in zh/en/ko/ja
- the eight basics cards present in all four languages
- Moka 9×9 assets present, model size matches its manifest, attribution files shipped
- 20 lessons and 300 drill setups/solutions legal
- opponent legality on 9×9 and 19×19
- review point count
- library save/open/delete
- spaced-review ladder and due puzzle selection

Static asset checks are intentionally limited to source inputs; the bundle and
`frontend/dist` are generated by `npm run build` and `npm run sync`.

  captures the white stone, `1/1` and “lesson complete” appear, Next works

- daily session starts from the Daily tab

- Review of a 6-move game shows the evaluation curve, summary and result
- Library lists records, Open loads a record, Export downloads a valid SGF,
  Delete removes a record
- SGF import via the hidden file input loads the record and shows a warning
  toast only on failure
- theme switching to Night and back to Wood; coordinates toggle; move-number
  toggle draws numbers on stones
- 390×844 and 720×720 layouts: rail collapses to icons, board remains

## Bugs found and fixed during acceptance

- Lesson/tsumego setup stones were passed as `{x, y, c}` while `Game.setup`
  read `color`; every course board was empty.
- A restored or imported SGF opened at move 0, so Review said “no game”.
- Hiding the board for Settings shrank the canvas to 1×1, produced a negative
  cell size and made `createRadialGradient` throw; the rest of the render was
  skipped and the UI could mix Play's top bar with the previous side panel.
  Geometry and stone radius are now clamped.
- Theme swatches used inline `style` attributes, which the page CSP blocked.
- Library had duplicate Import/New game actions in the top bar and page.
- The `Move numbers` setting was stored but never drawn.
- Puzzle “Next” did nothing because it only handled lessons.
- Daily context leaked into manually opened puzzles.
- Undo could leave the computer to move without scheduling its reply, and
  could leave discarded branches in the SGF.
- SGF export omitted root setup stones and used only the current node's
  result; import mis-parsed `YYYY-MM-DD` dates.
- Importing a record immediately let the AI answer its last move.

## Native shell checks

- `native validate` — `app.zon` is valid.
- `native test -Dplatform=null` — 3/3 Zig tests pass (production source,
  Windows path unescaping, plain path).
- `native build -Dplatform=null` — ReleaseFast executable links and builds.
- Native file open/save dialogs are wired through the Native SDK web API,
  with a browser file-input/download fallback.
- OS open-with events are forwarded by `src/main.zig` to the page as
  `open:files`; drag/drop uses `drop:files`. The native event delivery itself
  has not been exercised on a real macOS/Windows session.

## Not verified in this environment

- macOS/Windows WebView packaging, rendering, code signing, notarization,
  auto-update and the GTK/WebView Linux host. The null backend has no window,
  so it proves compilation, not desktop behavior.
- OS “open with” delivery for `.sgf` and drag/drop on a real desktop session.
- WKWebView/WebView2 download behavior for the SGF export fallback.
- Real Safari/WebKit and real Windows touch hardware.
- KataGo, professional-level strength, large-curriculum content review and
  store submission.
