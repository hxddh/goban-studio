## Dependency audit (2026-11-01)

- Native SDK 0.11.0 is the latest release. It requires Node.js 24 or newer.
- Zig stays at 0.16.0: Native SDK 0.11.0 pins that toolchain and rejects Zig
  0.17 as incompatible. Upgrading Zig alone would break every desktop build.
- Node.js 26 is the latest LTS in CI; the package declares Node.js 24 as its
  minimum because that is the Native SDK's own floor.
- KataGo 1.18.1 is the latest release with official Eigen CPU builds. KataGo
  1.18.2 only changes the CUDA Turing attention path, publishes no Eigen
  binary, and gives this CPU sidecar no functional benefit.
- The b6c96 network stays deliberately: the latest mainline transformer
  networks are 200 MB or more and would make the CPU sidecar slow. The engine
  is labelled by visit budget, not as a GPU-scale analysis engine.
- Moka v2.1 is current upstream (`millionco/moka`); the manifest and weights
  hashes match the upstream files exactly.
- `@sabaki/go-board` 1.4.3 and `esbuild` 0.28.2 are the latest releases.
- The bundled Inter file matches `@fontsource-variable/inter` 5.3.0, the latest
  font package.
- GitHub Actions use checkout v7, setup-node v7, upload-artifact v7 and
  download-artifact v8. `npm audit` reports zero vulnerabilities.

## Bugs found and fixed during acceptance

- Lesson/tsumego setup stones were passed as `{x, y, c}` while `Game.setup`
  read `color`; every course board was empty.
- A restored or imported SGF opened at move 0, so Review said “no game”.
- Hiding the board for Settings shrank the canvas to 1×1, produced a negative
  cell size and made `createRadialGradient` throw; the rest of the render was
  skipped and the UI could mix Play's top bar with the previous side panel.
  Geometry and stone radius are now clamped.
- Theme swatches used inline `style` attributes, which the page CSP blocked.
- Library had duplicate Import/New game actions in the top bar and page.
- The `Move numbers` setting was stored but never drawn.
- Puzzle “Next” did nothing because it only handled lessons.
- Daily context leaked into manually opened puzzles.
- Undo could leave the computer to move without scheduling its reply, and
  could leave discarded branches in the SGF.
- SGF export omitted root setup stones and used only the current node's
  result; import mis-parsed `YYYY-MM-DD` dates.
- Importing a record immediately let the AI answer its last move.
- SGF coordinates counted I as a column, shifting every imported stone from
  J onward one line. Parser, exporter and the generated opening cards now
  skip I like the board labels.
- The six Learn tabs wrapped into an uneven row; they now use a 3×2 grid.
- A classic game opened at its final move; it now opens at the empty board.
- The KataGo binary exceeds the SDK per-asset 16 MiB cap, so it is copied into
  the package after `native package`, not through the asset bundler.

## Native shell checks

- `native validate` — `app.zon` is valid.
- `native test -Dplatform=null` — 5/5 Zig tests pass (production source,
  Windows path unescaping, plain path, engine script vocabulary).
- `native build -Dplatform=null` — ReleaseFast executable links and builds.
- Direct Linux KataGo v1.18.1 probe: model loads and returns one 19×19 GTP
  move in about 1.1 s cold; two moves in one process take about 1.7 s total.
- `native package --target linux --assets frontend/dist` plus
  `scripts/install-engine.mjs` produces the expected
  `resources/frontend/dist/engine/{model,linux}` layout.
- Native file open/save dialogs are wired through the Native SDK web API,
  with a browser file-input/download fallback.
- OS open-with events are forwarded by `src/main.zig` to the page as
  `open:files`; drag/drop uses `drop:files`. The native event delivery itself
  has not been exercised on a real macOS/Windows session.

  so it proves compilation, not desktop behavior.
- OS “open with” delivery for `.sgf` and drag/drop on a real desktop session.
- WKWebView/WebView2 download behavior for the SGF export fallback.
- Real Safari/WebKit and real Windows touch hardware.
- KataGo inside the packaged macOS/Windows app, the native bridge on a real
  desktop WebView, store submission, notarization and auto-update.
- Professional review of the 60 lessons, 40 opening cards and 20 classic
  annotations. The content is complete and machine-validated, not
  professionally reviewed.
